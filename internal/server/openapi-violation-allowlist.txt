# Allowlisted response-shape deviations from the vendored DOTCOM OpenAPI
# description (testdata/github-openapi.json.gz, pinned in
# testdata/github-openapi.VERSION). Format per line:
#   op<TAB>kind<TAB>field   (see openapi_shape_validator_test.go)
#
# This is the only copy; TestViolationAllowlistIsSingleCopy fails if a
# second one appears. The list may only shrink. Every block states what
# was actually checked: either a citation into an official GitHub
# description that carries the member, or — where no such citation
# exists — a plain statement that the member is unverified and that the
# emitter, not this file, is what has to change.
#
# VERIFIED: installed_version is declared by api-overview in GitHub's
# ghes-3.21 description (descriptions/ghes-3.21/ghes-3.21.json at
# github/rest-api-description commit
# 16bc535ad66fac59d585b1516d1d52f58f787962) and absent from the dotcom
# one. bleephub reports installed_version 3.21.0 and gh CLI's feature
# detection resolves the host version from it.
GET /meta -> 200	unknown-field	$.installed_version

# VERIFIED: GitHub's official "Get repository content"
# documentation says that submodule responses carry submodule_git_url,
# including when a directory response returns one object per entry. The
# vendored dotcom schema models only the common directory-entry members
# and omits this documented discriminator-specific field.
GET /repos/{}/{}/contents/{} -> 200	unknown-field	$[].submodule_git_url

# VERIFIED: pushed_at is null in real GitHub for a repository that has never
# been pushed to (a freshly created / empty repo). GitHub's own `repository`
# and `minimal-repository` schemas model pushed_at as nullable; only
# `full-repository` and `repo-search-result-item` mark it non-nullable, an
# imprecision in the vendored dotcom description rather than a bleephub bug —
# bleephub emits nullableTimestamp(repo.PushedAt) faithfully (PAR-009).
GET /repos/{}/{} -> 200	null-not-allowed	$.pushed_at
GET /search/repositories -> 200	null-not-allowed	$.items[].pushed_at
PATCH /repos/{}/{} -> 200	null-not-allowed	$.pushed_at
POST /orgs/{}/repos -> 201	null-not-allowed	$.pushed_at
POST /repos/{}/{}/forks -> 202	null-not-allowed	$.pushed_at
POST /user/codespaces/{}/publish -> 201	null-not-allowed	$.repository.pushed_at
POST /user/repos -> 201	null-not-allowed	$.pushed_at

# VERIFIED: an enterprise team's description is null when unset. GitHub's
# `team` and `nullable-team-simple` schemas model description as a nullable
# member; only `enterprise-team` marks it non-nullable, an imprecision in the
# vendored description. bleephub emits nullOrString(team.Description) (PAR-009).
PATCH /enterprises/{}/teams/{} -> 200	null-not-allowed	$.description
POST /enterprises/{}/teams -> 201	null-not-allowed	$.description

# VERIFIED: placeholder_id and token_type are the dotcom description's own
# secret-scanning push-protection members — the
# `secret-scanning-push-protection-bypass-placeholder-id` schema and the
# delegated-bypass flow define exactly these fields. bleephub applies push
# protection to REST ref creation (a deliberate feature: creating a ref that
# introduces a blocked secret returns the bypass contract a secret-scanning
# client needs to drive POST /secret-scanning/push-protection-bypasses), and
# the description simply does not model push protection on the git/refs 422,
# whose schema stops at plain validation-error. Owner decision 2026-08-11
# (ledger PAR-013): keep the richer error contract rather than degrade the
# feature to the sparser documented shape.
POST /repos/{}/{}/git/refs -> 422	unknown-field	$.placeholder_id
POST /repos/{}/{}/git/refs -> 422	unknown-field	$.token_type
POST /repos/{}/{}/git/refs -> 422	unknown-field	$.errors[].placeholder_id
POST /repos/{}/{}/git/refs -> 422	unknown-field	$.errors[].token_type

# VERIFIED deviation, kept by owner decision 2026-08-11 (ledger PAR-010):
# bleephub's authorization model has a load-bearing `admin` permission level
# (permAdmin) that many installation grants and tests depend on; GitHub's
# app-permission enums stop at read/write for these three fields. Degrading
# bleephub's admin authz to conform would weaken a real access-control
# distinction, so the enum deviation is deliberate. The values are otherwise
# schema-typed strings and every other permission field conforms.
GET /orgs/{}/installations -> 200	enum-mismatch	$.installations[].permissions.administration
GET /orgs/{}/installations -> 200	enum-mismatch	$.installations[].permissions.organization_administration
GET /orgs/{}/installations -> 200	enum-mismatch	$.installations[].permissions.organization_hooks
GET /user/installations -> 200	enum-mismatch	$.installations[].permissions.administration
GET /user/installations -> 200	enum-mismatch	$.installations[].permissions.organization_administration
GET /user/installations -> 200	enum-mismatch	$.installations[].permissions.organization_hooks

# VERIFIED deviation, kept by owner decision 2026-08-11 (ledger PAR-010):
# approval_policy `none` encodes "fork-PR approval disabled", a real
# configuration state GitHub's enum (all_external_contributors /
# first_time_contributors / first_time_contributors_new_to_github) does not
# model; the fork-PR workflow-trigger gating keys off `none`, and mapping it
# onto any documented member would either lie about the setting or change
# trigger behaviour (TestForkPullRequestTriggersWithTheBaseWorkflowDefinition).
GET /repos/{}/{}/actions/permissions/fork-pr-contributor-approval -> 200	enum-mismatch	$.approval_policy
